§a§
 This is a known PaddlePaddle 3.3.x regression when running **PP-OCRv5/v6 models through `paddle_static` with OneDNN + PIR** ([PaddleOCR#18119](https://github.com/PaddlePaddle/PaddleOCR/issues/18119), [PaddleOCR#17869](https://github.com/PaddlePaddle/PaddleOCR/issues/17869)). PaddleX/PaddleOCR internally re-enables PIR when setting the device, so your current `os.environ` flags are being set too late.

Here are the fixes, from quickest to most robust:

### 1. Set environment variables BEFORE any paddle import
Move the flags to the **very first lines** of `main.py`, before any `import paddle`, `from paddleocr import ...`, `import paddlex`, etc. Once those modules are imported, the flags are often ignored or overwritten.

```python
# main.py — must be at the very top
import os

os.environ['FLAGS_use_mkldnn'] = '0'
os.environ['FLAGS_enable_pir_in_executor'] = '0'
os.environ['FLAGS_enable_pir_api'] = '0'  # <-- this is the key flag

# ... then your other imports
```

If PaddleOCR is imported globally (e.g. `from paddleocr import PaddleOCR` at the top), this must be fixed first, because by then `paddlex` already forced `FLAGS_enable_pir_api=1`.

### 2. Disable MKLDNN in the constructor
Even with the env flags, pass `enable_mkldnn=False` explicitly:

```python
ocr = PaddleOCR(
    use_doc_orientation_classify=False,
    use_doc_unwarping=False,
    use_textline_orientation=False,
    enable_mkldnn=False,   # force-disable OneDNN
)
```

### 3. Downgrade PaddlePaddle (most reliable workaround)
The bug was introduced around PaddlePaddle 3.3. Several reports confirm that downgrading fixes it:

```bash
pip install "paddlepaddle==3.2.2"
```

If you are using GPU, use `paddlepaddle-gpu` instead:

```bash
pip install "paddlepaddle-gpu==3.2.2"
```

### 4. Upgrade once a fixed build is available
The exact crash (`pir::ArrayAttribute<pir::DoubleAttribute>` not supported) was fixed upstream in PaddlePaddle commit [`12bff20`](https://github.com/PaddlePaddle/Paddle/commit/12bff203b6289c32a79f81a462eda5048cdc2c6a) (April 2026). You can also wait for a stable 3.3 patch release that includes that commit.

### Recommended immediate change
Apply both #1 and #2:

```python
import os
os.environ['FLAGS_use_mkldnn'] = '0'
os.environ['FLAGS_enable_pir_in_executor'] = '0'
os.environ['FLAGS_enable_pir_api'] = '0'

from paddleocr import PaddleOCR

# ... your existing code ...

elif ENGINE[0] == 'paddleocr':
    ocr = PaddleOCR(
        use_doc_orientation_classify=False,
        use_doc_unwarping=False,
        use_textline_orientation=False,
        enable_mkldnn=False,
    )
    lines = []
    for res in ocr.predict('_warped_image.png'):
        rec_texts = res.json['res']['rec_texts']
        lines.extend(t.strip() for t in rec_texts if t and t.strip())
    text = '\n'.join(lines)
```

If the above still fails, downgrade to `paddlepaddle==3.2.2` — that combination is confirmed working for PP-OCRv5/v6.

The other warnings (`ROCM_HOME`, TorchVision `pretrained`, `libcudnn_cnn_infer.so.8`, ccache) are unrelated to this crash; you can address them separately later.
