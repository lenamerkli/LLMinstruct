This is **not really an Epic account logout/login problem**. Heroic is calling **Legendary** for Epic login, and Legendary is crashing before/while authenticating because Python cannot verify the TLS certificate chain for `api.legendary.gl`. Heroic uses Legendary for Epic Games support, and the traceback is inside Legendary’s bundled Python/Requests stack.

## 1) Check the easy cause first: system date/time

Run:

```bash
timedatectl status
```

If the time/date is wrong:

```bash
sudo timedatectl set-ntp true
```

Then fully close Heroic and try again.

---

## 2) Reinstall/update your system CA certificates

Your path `/usr/lib64/...` suggests Fedora/openSUSE/Arch-ish packaging, so use the section that matches your distro.

### Fedora / RHEL / Nobara / Bazzite-like

```bash
sudo dnf reinstall ca-certificates
sudo update-ca-trust extract
```

Red Hat/Fedora-style systems use a system-wide trust store under `/etc/pki/ca-trust/`, and `update-ca-trust` applies changes to it.

### openSUSE Tumbleweed / Leap

```bash
sudo zypper install -f ca-certificates ca-certificates-mozilla
sudo update-ca-certificates -f
```

On SUSE/openSUSE, `update-ca-certificates` synchronizes system certificate stores, and admin-added trust anchors live under `/etc/pki/trust/anchors`.

### Arch / EndeavourOS / Manjaro

```bash
sudo pacman -Syu ca-certificates ca-certificates-mozilla ca-certificates-utils
sudo update-ca-trust extract
```

Arch’s `update-ca-trust` generates CA bundle files under `/etc/ca-certificates/extracted/` and compatibility links under `/etc/ssl/certs/`.

### Debian / Ubuntu / Mint

```bash
sudo apt update
sudo apt install --reinstall ca-certificates
sudo update-ca-certificates -f
```

On Debian-style systems, `update-ca-certificates` manages `/etc/ssl/certs` and generates `/etc/ssl/certs/ca-certificates.crt`.

After that, reboot or at least log out/in, then try Heroic again.

---

## 3) Test whether your system can verify Legendary’s HTTPS endpoint

Run:

```bash
curl -Iv https://api.legendary.gl/v1/version.json
```

Expected: no `SSL certificate problem` / no `unable to get local issuer certificate`.

If `curl` also fails, the issue is system-wide: CA store, clock, VPN/proxy, or network interception.

If `curl` works but Heroic still fails, Heroic/Legendary’s Python runtime is not finding the same CA bundle.

---

## 4) If curl works but Heroic still fails: force Heroic to use your system CA bundle

Find your CA bundle:

```bash
for f in \
  /etc/pki/tls/certs/ca-bundle.crt \
  /etc/ssl/certs/ca-certificates.crt \
  /etc/ssl/ca-bundle.pem \
  /var/lib/ca-certificates/ca-bundle.pem \
  /etc/ssl/certs/ca-bundle.crt
do
  [ -s "$f" ] && echo "$f"
done
```

Pick the path that exists. Then launch Heroic from a terminal like this, replacing the path if needed:

```bash
SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt \
REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt \
heroic
```

or on Fedora/RHEL/openSUSE if that path exists:

```bash
SSL_CERT_FILE=/etc/pki/tls/certs/ca-bundle.crt \
REQUESTS_CA_BUNDLE=/etc/pki/tls/certs/ca-bundle.crt \
heroic
```

Python Requests supports `REQUESTS_CA_BUNDLE`, falling back to `CURL_CA_BUNDLE`, when you need to point it at a CA bundle file.

If that fixes it, make it permanent by copying Heroic’s desktop entry and editing its `Exec=` line:

```bash
mkdir -p ~/.local/share/applications
cp /usr/share/applications/*heroic*.desktop ~/.local/share/applications/ 2>/dev/null
```

Open the copied `.desktop` file:

```bash
nano ~/.local/share/applications/*heroic*.desktop
```

Change the `Exec=` line from something like:

```ini
Exec=heroic %U
```

to:

```ini
Exec=env SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt heroic %U
```

Use the CA bundle path that exists on your system.

## 5) If you are on school/work Wi‑Fi, VPN, Zscaler, corporate proxy, etc.

A TLS-intercepting proxy can cause exactly this. Browsers may work because they trust the organization’s root CA, while Python/Requests may not. Requests’ docs specifically note that HTTPS proxies typically require your machine to trust the proxy’s root certificate.

Only do this if you trust the network/admin CA.

### Fedora/RHEL

```bash
sudo cp YourCompanyRootCA.crt /etc/pki/ca-trust/source/anchors/
sudo update-ca-trust extract
```

### openSUSE

```bash
sudo cp YourCompanyRootCA.crt /etc/pki/trust/anchors/
sudo update-ca-certificates
```

### Debian/Ubuntu

```bash
sudo cp YourCompanyRootCA.crt /usr/local/share/ca-certificates/
sudo update-ca-certificates
```

### Arch

```bash
sudo cp YourCompanyRootCA.crt /etc/ca-certificates/trust-source/anchors/
sudo update-ca-trust extract
```

Then restart Heroic.

flatpak install flathub com.heroicgameslauncher.hgl

## 7) What **not** to do

Do **not** disable TLS verification globally or patch Legendary to use `verify=False`. Requests warns that disabling verification accepts any certificate and makes you vulnerable to man-in-the-middle attacks.
