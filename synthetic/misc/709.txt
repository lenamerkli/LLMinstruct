## Shutting Down Nextcloud AIO Permanently (Until You Want It Back)

Looking at your `docker ps -a` output, only the **mastercontainer** is currently running — it's the orchestrator that starts all the other containers. Here's what to do:

### Step 1 — Remove the auto-restart policy

The mastercontainer almost certainly has a `restart: always` or `restart: unless-stopped` policy, which is why Docker keeps it alive. Override it:

```bash
docker update --restart=no nextcloud-aio-mastercontainer
```

### Step 2 — Stop the mastercontainer

```bash
docker stop nextcloud-aio-mastercontainer
```

### Step 3 — Verify nothing is running

```bash
docker ps
```
The output should be empty (or show only unrelated containers).

---

### To bring it back up when you want it

Simply start the mastercontainer again:
```bash
docker start nextcloud-aio-mastercontainer
```
Then log into the AIO interface (`:8080`) and start the stack from there. If you want auto-restart re-enabled for future reboots:
```bash
docker update --restart=always nextcloud-aio-mastercontainer
```

---

### Why not just `docker stop`?

Without the `docker update --restart=no` step first, if Docker's daemon restarts (e.g. after a server reboot), it would automatically bring the mastercontainer back up based on its restart policy — which is likely not what you want.
