## How Messages Are Stored

### Database Technology
StoatChat uses **MongoDB** as its primary database. Messages are stored in a collection called `messages`.

### Message Schema

The `Message` struct (defined in `crates/core/database/src/models/messages/model.rs`) has the following fields:

```rust
pub struct Message {
    pub id: String,                    // ULID format (e.g., "01HXYZ...")
    pub nonce: Option<String>,         // Client-generated idempotency key
    pub channel: String,               // Channel ID
    pub author: String,                // User or webhook ID
    pub webhook: Option<MessageWebhook>,
    pub content: Option<String>,       // Message text
    pub system: Option<SystemMessage>, // System events (user joined, etc.)
    pub attachments: Option<Vec<File>>,
    pub edited: Option<Timestamp>,
    pub embeds: Option<Vec<Embed>>,
    pub mentions: Option<Vec<String>>,     // User IDs mentioned
    pub role_mentions: Option<Vec<String>>, // Role IDs mentioned
    pub replies: Option<Vec<String>>,      // Message IDs being replied to
    pub reactions: IndexMap<String, IndexSet<String>>, // emoji -> user IDs
    pub interactions: Interactions,
    pub masquerade: Option<Masquerade>,    // Name/avatar override
    pub pinned: Option<bool>,
    pub flags: Option<u32>,                // Bitfield for mentions_everyone, etc.
}
```

### Migration Options

For inserting custom messages from another chat app, you have several approaches:

#### Option 1: Direct MongoDB Insert (Recommended for bulk migration)
Insert documents directly into the `messages` collection in MongoDB. You'll need to:
1. Generate ULID IDs for messages (sorted by timestamp)
2. Ensure `channel` and `author` IDs exist in the database
3. Follow the document structure above

Example MongoDB document:
```json
{
  "_id": "01HXYZ123456789",
  "channel": "channel_id_here",
  "author": "user_id_here",
  "content": "Hello, this is a migrated message!",
  "reactions": {}
}
```

#### Option 2: Use the API
Send messages through the `/channels/{target}/messages` REST endpoint. This handles validation, permissions, and events but is slower for bulk imports.

#### Option 3: Create a Custom Import Script
Write a Rust script using the existing `Database` and `Message` types to insert messages directly.

### Important Considerations

1. **ID Format**: Message IDs are ULIDs (time-sortable). Use the `ulid` crate or library to generate them based on original timestamps.

2. **Referential Integrity**: Ensure `channel` and `author` IDs exist before inserting messages.

3. **System Messages**: The `SystemMessage` enum handles special events like `UserJoined`, `UserLeft`, etc.

4. **Files/Attachments**: If migrating attachments, you'll also need to handle the `files` collection and storage backend.

5. **Events**: Direct database inserts won't trigger WebSocket events. For live migration, you may want to broadcast `Message` events after insertion.
