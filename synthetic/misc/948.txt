==Crushing Speed==
There are 4 variables that effect the processing speed of the Crushing Wheel: RPM, stack size, recipe duration, input delay. The recipe duration is a number assigned to each recipe as shown in the following table below. The input delay is the number of ticks it takes for an item to be inserted into the crushing wheels, The input delay is set by the component inserting the items and is 1 for any funnel, 3 for any chute, and 27 if thrown directly to the crushing wheel. Be aware that the use of belts to feed the funnel will add more delay.

=== Crushing Speed Formula ===
To calculate the exact number of game ticks it take to process an input, use this formula:

<math>\text{processing time (ticks per stack size)} = \left\lfloor \frac{\text{recipe duration in ticks} - 20}{\max \left(0.25, \min \left( \frac{\frac{\text{RPM}} \text{50} \times 4}{\log_2(\text{stack size})}, 20 \right)\right) } \right\rfloor + 1 + \text{input delay} </math>

How many sets of crushing wheels do I need to crush tuff with 256 RPM and 64 Stack size?
§a§
To determine exactly how many sets of crushing wheels you need, you must first define your **target throughput** (how many items you want to process per second), which isn't specified in your question.

However, you only need **1 set** of crushing wheels to process the Tuff. Here is the exact calculation of how fast a single set will process a stack of 64 Tuff at 256 RPM, which you can use to scale up your factory.

### 1. Identify the Variables
*   **Item:** Tuff
*   **Recipe Duration:** 350 ticks (from the table)
*   **RPM:** 256
*   **Stack Size:** 64
*   **Input Delay:** 1 tick (assuming you use a **funnel**, which is standard for automation. It would be 3 for a chute, or 27 if thrown).

### 2. Calculate the Speed Multiplier
First, we solve the inner part of the formula: $\frac{\frac{\text{RPM}}{50} \times 4}{\log_2(\text{stack size})}$
*   $\text{RPM} / 50 = 256 / 50 = 5.12$
*   $5.12 \times 4 = 20.48$
*   $\log_2(64) = 6$
*   $20.48 / 6 \approx 3.4133$

Next, apply the `min` and `max` boundaries:
*   $\min(3.4133, 20) = 3.4133$
*   $\max(0.25, 3.4133) = 3.4133$

### 3. Calculate the Processing Time
Now we plug the multiplier into the main formula:
$$ \text{processing time} = \left\lfloor \frac{350 - 20}{3.4133} \right\rfloor + 1 + \text{input delay} $$

*   $350 - 20 = 330$
*   $330 / 3.4133 \approx 96.679$
*   $\lfloor 96.679 \rfloor = 96$
*   $96 + 1 = 97$

Finally, add the input delay based on how you are feeding the wheels:
*   **With a Funnel (1 tick delay):** 97 + 1 = **98 ticks per stack** (4.9 seconds)
*   **With a Chute (3 tick delay):** 97 + 3 = **100 ticks per stack** (5.0 seconds)
*   **Thrown directly (27 tick delay):** 97 + 27 = **124 ticks per stack** (6.2 seconds)

### 4. How many sets do you need?
Assuming you use a funnel, **one set of crushing wheels will process 64 Tuff every 98 ticks.**
Since Minecraft runs at 20 ticks per second, one set yields a throughput of:
*   $64 \text{ items} / 4.9 \text{ seconds} \approx$ **13.06 items per second**.

To find out how many sets you need, divide your desired items-per-second by 13.06 and round up.
*   **Example 1:** If you want to process **100 Tuff per second**, you need `100 / 13.06 = 7.65`. You would need **8 sets** of crushing wheels.
*   **Example 2:** If you just want to process a single chest of Tuff (1,728 items) as fast as possible, 1 set will take about 132 seconds, while **10 sets** working in parallel will finish the chest in just over 13 seconds.
