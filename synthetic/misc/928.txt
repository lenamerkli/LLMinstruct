Why does this map not show up in Beamng?
§a§
Most likely: **the ZIP is packaged one folder too deep**.

BeamNG wants the **root of the zip** to contain `levels/...`, like this:

```text
monaco_but_worse.zip
└── levels
    └── monaco_but_worse
        ├── info.json
        ├── main.level.json
        ├── main.materials.json
        ├── art/
        └── textures/
```

But your working tree is:

```text
monaco_but_worse/
└── levels/
    └── monaco_but_worse/
        ...
```

So if you zipped that whole `monaco_but_worse` folder, the zip probably contains:

```text
monaco_but_worse/levels/monaco_but_worse/...
```

BeamNG usually **won’t scan that as a level**, because it expects `levels/...` at the zip root, not `monaco_but_worse/levels/...`.

## How to verify

Run:

```bash
zipinfo -1 ~/.steam/steam/steamapps/compatdata/284160/pfx/drive_c/users/steamuser/AppData/Local/BeamNG/BeamNG.drive/current/mods/monaco_but_worse.zip | head -20
```

If you see:

```text
monaco_but_worse/levels/monaco_but_worse/info.json
```

that’s the problem.

If it instead starts with:

```text
levels/monaco_but_worse/info.json
```

then the structure is correct.

## How to fix

Rebuild the zip so `levels/` is at the top level of the archive.

From your `out` directory, do something like:

```bash
cd monaco_but_worse
zip -r ../monaco_but_worse.zip levels
```

Then copy that new zip into BeamNG’s mods folder.

## Also do this after repacking

BeamNG caches mod data pretty aggressively. After replacing the zip:

- delete `db.json`, or
- use BeamNG’s **Clear Cache** option,
- then restart the game.

You already showed:

```text
mods/
├── db.json
└── monaco_but_worse.zip
```

So clearing that cache is worth doing.
