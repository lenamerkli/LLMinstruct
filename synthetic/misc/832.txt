§u§
What is the best way to implement viewing websites for LLM's? Like removing styling and javascript.
§a§
The best approach is **not just “strip CSS/JS and dump text”**. Build a small **browser-to-LLM adapter** that produces a few LLM-friendly views of the page:

1. **Reader/content view** — clean article/body content as Markdown.
2. **Accessibility/action view** — buttons, links, inputs, headings, roles, labels, states.
3. **Fallback DOM outline** — for poorly accessible sites where the accessibility tree misses things.
4. **Optional visual view** — screenshot/OCR/captioning for canvas, charts, images, maps, etc.

## Recommended architecture

### 1. Start with static fetch when possible

For normal pages, docs, blogs, news, etc.:

- `GET` the HTML.
- Parse with a real HTML parser, not regex.
- Remove:
  - `<script>`
  - `<style>`
  - tracking pixels
  - ads
  - cookie banners
  - nav/footer/sidebar boilerplate when possible
- Preserve:
  - headings
  - paragraphs
  - lists
  - tables
  - code blocks
  - links
  - image alt text/captions
  - forms and labels
- Run a main-content extractor like **Mozilla Readability**.
- Convert cleaned HTML to Markdown.

Mozilla Readability is the same kind of library used for Firefox Reader View; its `parse()` output includes processed article HTML, plain text, title, excerpt, byline, site name, language, and other metadata.  Turndown is a common JS library for converting HTML or DOM nodes into Markdown.

Good output shape:

```json
{
  "url": "https://example.com/post",
  "title": "Post title",
  "content_markdown": "# Post title\n\nClean page text...",
  "links": [
    { "id": "L1", "text": "Pricing", "href": "https://example.com/pricing" }
  ],
  "metadata": {
    "description": "...",
    "published_time": "...",
    "site_name": "Example"
  }
}
```

### 2. Use a headless browser only when needed

Many modern sites are SPAs and the initial HTML is nearly empty. For those:

- Use Playwright/Puppeteer.
- Load the page in a sandboxed browser.
- Optionally disable JavaScript first.
- If the page is blank or incomplete, enable JS and render.
- After rendering, serialize the **resulting DOM/text**, not the original scripts.
- Block unnecessary resources where safe: images, video, fonts, trackers, analytics.

Playwright supports creating browser contexts with `javaScriptEnabled: false`, and its routing APIs can intercept or abort requests such as images or other resource types.

Important nuance: **CSS affects visibility**. If you remove CSS before determining what is visible, you may accidentally expose hidden menus, modals, tracking text, or prompt-injection bait. For rendered pages, compute visibility first, then strip styling.

### 3. Give the LLM an accessibility tree for interaction

For browsing agents, Markdown alone is not enough. The LLM needs to know what it can click, type into, select, expand, etc.

Use the page’s **accessibility tree** or an ARIA-like snapshot:

```yaml
- heading "Search results" [level=1]
- textbox "Search query" [value="llm browsers"]
- button "Search"
- link "OpenAI"
- link "Documentation"
```

Browsers create an accessibility tree from the DOM for assistive technologies, containing things like name, role, description, state, and possible actions.  Playwright’s ARIA snapshot format represents accessible elements as YAML with roles, names, attributes, values, and text content, and it can be generated programmatically with `page.ariaSnapshot()` or `locator.ariaSnapshot()`.

For an agent, augment that with stable internal IDs:

```json
{
  "controls": [
    {
      "id": "B1",
      "role": "button",
      "name": "Search",
      "selector": "internal-handle-123",
      "enabled": true,
      "visible": true
    },
    {
      "id": "I1",
      "role": "textbox",
      "name": "Search query",
      "value": "",
      "selector": "internal-handle-456"
    }
  ]
}
```

Then expose a small tool API:

```ts
click("B1")
type("I1", "query text")
select("S1", "option")
scroll("down")
open("L3")
```

Do **not** let the LLM execute arbitrary JavaScript on the page.

## Practical extraction pipeline

```text
URL
 ↓
Fetch HTML
 ↓
Is the page usable without JS?
 ├─ yes → parse → clean → Readability → Markdown + links
 └─ no  → render in Playwright → compute visible/semantic DOM → clean → Markdown + accessibility tree
 ↓
Chunk by headings/sections
 ↓
Send compact page view to LLM
 ↓
For actions, send only IDs + semantic descriptions
```

## Cleaning rules

### Remove

```css
script,
style,
link[rel="stylesheet"],
template,
iframe[src*="ads"],
[aria-hidden="true"],
[hidden],
nav:empty,
footer:empty,
svg.icon,
.cookie-banner,
.ad,
.tracker,
.modal-backdrop
```

But don’t blindly remove all:

- `<nav>` can matter on documentation sites.
- `<aside>` can contain table of contents.
- `<noscript>` can contain useful fallback content.
- Hidden elements may be useful after an action, but they should not be shown as current visible content.

### Preserve

```html
<title>
<meta name="description">
<main>
<article>
<section>
<h1>...<h6>
<p>
<ul>, <ol>, <li>
<table>, <thead>, <tbody>, <tr>, <th>, <td>
<pre>, <code>
<a href>
<img alt>
<form>
<label>
<input>
<textarea>
<select>
<button>
```

## Example Node implementation sketch

```ts
import { chromium } from "playwright";
import { JSDOM } from "jsdom";
import { Readability } from "@mozilla/readability";
import TurndownService from "turndown";
import DOMPurify from "dompurify";

const turndown = new TurndownService({
  headingStyle: "atx",
  codeBlockStyle: "fenced",
  linkStyle: "referenced"
});

export async function extractStatic(url: string) {
  const res = await fetch(url, {
    headers: {
      "Accept": "text/html,application/xhtml+xml"
    }
  });

  const html = await res.text();
  const dom = new JSDOM(html, { url });
  const { document } = dom.window;

  document
    .querySelectorAll("script, style, link[rel='stylesheet'], template")
    .forEach(el => el.remove());

  const clone = document.cloneNode(true) as Document;
  const article = new Readability(clone).parse();

  const contentHtml = article?.content ?? document.body.innerHTML;
  const markdown = turndown.turndown(contentHtml);

  return {
    url,
    title: article?.title ?? document.title,
    excerpt: article?.excerpt,
    byline: article?.byline,
    siteName: article?.siteName,
    markdown
  };
}
```

Rendered fallback:

```ts
export async function extractRendered(url: string) {
  const browser = await chromium.launch({ headless: true });

  const context = await browser.newContext({
    javaScriptEnabled: true,
    viewport: { width: 1280, height: 900 }
  });

  // Be careful: blocking CSS can make visibility detection inaccurate.
  // Usually block heavy media, but allow CSS if you need accurate layout/visibility.
  await context.route("**/*", route => {
    const type = route.request().resourceType();

    if (["image", "media", "font"].includes(type)) {
      return route.abort();
    }

    return route.continue();
  });

  const page = await context.newPage();

  await page.goto(url, {
    waitUntil: "domcontentloaded",
    timeout: 15000
  });

  await page.waitForLoadState("networkidle").catch(() => {});

  const pageData = await page.evaluate(() => {
    function isVisible(el: Element) {
      const style = window.getComputedStyle(el);
      const rect = el.getBoundingClientRect();

      return (
        style.display !== "none" &&
        style.visibility !== "hidden" &&
        style.opacity !== "0" &&
        rect.width > 0 &&
        rect.height > 0 &&
        !el.hasAttribute("hidden") &&
        el.getAttribute("aria-hidden") !== "true"
      );
    }

    const clone = document.body.cloneNode(true) as HTMLElement;

    clone
      .querySelectorAll("script, style, link, template, iframe")
      .forEach(el => el.remove());

    return {
      title: document.title,
      url: location.href,
      html: clone.innerHTML,
      text: document.body.innerText
    };
  });

  const markdown = turndown.turndown(pageData.html);

  let aria: string | null = null;

  try {
    // Available in modern Playwright versions.
    aria = await page.ariaSnapshot();
  } catch {
    aria = null;
  }

  await browser.close();

  return {
    ...pageData,
    markdown,
    aria
  };
}
```

If you render or display cleaned HTML anywhere, sanitize it. DOMPurify is designed to sanitize HTML and remove dangerous content such as XSS payloads.

## Best representation to send to the LLM

For reading:

```markdown
# Page title

Source: https://example.com

## Main heading

Paragraph text...

[1] Pricing — /pricing
[2] Docs — /docs
```

For interaction:

```text
Current page: Example
URL: https://example.com

Visible content:
- heading: Welcome to Example
- paragraph: Build applications faster...

Interactive elements:
[B1] button "Sign in"
[B2] button "Start free trial"
[L1] link "Pricing" -> /pricing
[I1] textbox "Email"
```

This is much better than raw HTML because:

- fewer tokens
- less noise
- keeps links/actions
- avoids script/style injection
- gives the model semantic structure
- supports deterministic tool actions

## Security considerations

Treat webpage content as **untrusted data**.

Recommended safeguards:

- Never let page text override system/developer instructions.
- Strip hidden text unless explicitly needed.
- Keep page content in a clearly delimited “untrusted page content” block.
- Do not expose cookies, local storage, auth headers, or secrets to the model.
- Do not allow arbitrary JS execution requested by the model.
- Run browser sessions in containers or sandboxes.
- Disable downloads, clipboard, camera, microphone, geolocation, and local file access.
- Block internal/private network targets to avoid SSRF.
- Enforce timeouts, max HTML size, max redirects, and max tokens.
- Cache fetched pages.
- Respect robots.txt and site terms where applicable.

## TL;DR

The best implementation is:

```text
Static pages:
  fetch HTML → parse DOM → Readability → Markdown

JS-heavy pages:
  Playwright render → compute visible DOM → clean → Markdown

Interactive browsing:
  accessibility tree + interactable IDs + small action API

Always:
  sanitize, sandbox, strip scripts/styles, preserve links/forms/tables/headings, treat page text as untrusted
```

In other words: **build a reader-mode plus screen-reader-style view**, not a raw browser dump.

## 🐍 Local / Open-Source Python Packages

### 1. **Crawl4AI** ⭐ (Best all-in-one, free)
The most purpose-built option for this exact use case. Crawl4AI is described as the best AI-ready output library, outputting clean Markdown/JSON for LLMs. Its primary job is the AI-ready extraction abstraction — use it when you need token-efficient Markdown or structured JSON natively output from your crawl to feed a RAG pipeline.

```bash
pip install crawl4ai
```
```python
import asyncio
from crawl4ai import AsyncWebCrawler

async def main():
    async with AsyncWebCrawler() as crawler:
        result = await crawler.arun(url="https://example.com")
        print(result.markdown)

asyncio.run(main())
```

---

### 2. **Trafilatura** ⭐ (Best for content extraction)
Specializes in pulling the main article/body content and stripping boilerplate. Trafilatura excels at extracting clean content while removing boilerplate. It also natively supports Markdown output.

```bash
pip install trafilatura
```
```python
import trafilatura

downloaded = trafilatura.fetch_url("https://example.com")
markdown = trafilatura.extract(downloaded, output_format="markdown")
print(markdown)
```

---

### 3. **html2text**
Originally developed by Aaron Swartz, html2text has been a staple in the Python ecosystem for over a decade and focuses on producing clean, readable Markdown output. It's simple but doesn't do content extraction (no boilerplate removal) on its own.

```bash
pip install html2text
```
```python
import html2text
import requests

h = html2text.HTML2Text()
h.ignore_links = False
html = requests.get("https://example.com").text
print(h.handle(html))
```

---

### 4. **markdownify**
A popular option is to use `requests` to make the GET request and get the page HTML as a string, and `markdownify` to convert the HTML of the page into Markdown. Like `html2text`, it's a converter only — pair it with BeautifulSoup for cleaning first.

```bash
pip install markdownify beautifulsoup4
```
```python
from bs4 import BeautifulSoup
from markdownify import markdownify
import requests

html = requests.get("https://example.com").text
soup = BeautifulSoup(html, "html.parser")
for tag in soup(["script", "style", "nav", "footer"]):
    tag.decompose()
print(markdownify(str(soup)))
```

---

### 5. **ScrapeGraphAI**
ScrapeGraphAI is a Python web scraping library that combines LLMs and direct graph logic to build scraping pipelines for websites and local documents like XML, HTML, JSON, and Markdown. It's more expensive since it uses LLM inference per page, but very flexible.

```bash
pip install scrapegraphai
```

---

## ☁️ API-Based Services (with Python SDKs)

These handle JS rendering, anti-bot measures, and clean Markdown output for you:

### 6. **Firecrawl** (`firecrawl-py`)
Firecrawl returns clean Markdown by default, optimized for LLM context windows. You can also get raw HTML, screenshots, page metadata, and structured JSON via schemas. Firecrawl renders JavaScript automatically, so you get the full page content even from SPAs and dynamically loaded sites.

```bash
pip install firecrawl-py
```
```python
from firecrawl import FirecrawlApp

app = FirecrawlApp(api_key="fc-YOUR_KEY")
result = app.scrape_url("https://example.com", formats=["markdown"])
print(result.markdown)
```

---

### 7. **LlamaParse** (from LlamaIndex)
LlamaParse is a high-quality parser from LlamaIndex that extracts structured content from documents — including PDFs, HTML, and web pages. It's built to work seamlessly with LLMs like GPT, Claude, or local models via Ollama.

## 🏆 Recommendation

- **Free + local + JS sites** → **Crawl4AI** (purpose-built for LLMs, handles rendering)
- **Free + static content/articles** → **Trafilatura** (best boilerplate removal)
- **Simple static conversion** → **html2text** or **markdownify** + **BeautifulSoup**
- **Production-scale pipelines** → **Firecrawl** (managed, reliable)
- **Schema-driven structured extraction** → **ScrapeGraphAI**
