What do I have to change in this code so that if the models ends with `</tool_call>` or `</invoke>`, that string is appended at the end of the response?
§a§
Because OpenRouter (and the OpenAI standard it follows) strips the stop string from the final response and only returns a generic `finish_reason: "stop"`, the API won't tell you *which* stop string triggered the halt.

However, because your stop sequences are closing XML tags (`</tool_call>` and `</invoke>`), we can use a highly reliable heuristic: **when the model stops, we check the generated text to see which tag is currently "open" (unclosed) and append the matching closing tag.**

Here is how you can update your code. Look for the `try:` block inside your chunk processor and update the `json.loads` portion to this:

```python
                    try:
                        chunk = json.loads(data_str)

                        # Check for mid-stream error
                        if 'error' in chunk:
                            print(f"Stream error: {chunk['error'].get('message', 'unknown error')}")
                            stream_finished = True
                            break

                        # Extract the choice object to get both delta and finish_reason
                        choice = chunk.get('choices', [{}])[0]
                        delta = choice.get('delta', {})

                        # Accumulate content and thinking
                        content = delta.get('content', '') or ''
                        thinking = delta.get('reasoning', '') or ''

                        if content:
                            full_content += content
                            print(content, end="", flush=True)
                            on_token(content)

                        if thinking:
                            full_thinking += thinking

                        # Grab usage/cost from any chunk that includes it
                        usage = chunk.get('usage', {}) or {}
                        if 'cost' in usage:
                            total_cost = usage['cost']

                        # --- NEW CODE: Detect stop and append the closing tag ---
                        finish_reason = choice.get('finish_reason')
                        if finish_reason == 'stop':
                            # Find which tag is currently "open" (missing its closing pair)
                            # We use '<tool_call' without '>' to safely catch tags with attributes like <tool_call name="xyz">
                            open_tool_call = full_content.rfind('<tool_call') > full_content.rfind('</tool_call>')
                            open_invoke = full_content.rfind('<invoke') > full_content.rfind('</invoke>')

                            append_str = ""
                            if open_tool_call and open_invoke:
                                # If somehow both are open, pick the one opened most recently
                                if full_content.rfind('<tool_call') > full_content.rfind('<invoke'):
                                    append_str = '</tool_call>'
                                else:
                                    append_str = '</invoke>'
                            elif open_tool_call:
                                append_str = '</tool_call>'
                            elif open_invoke:
                                append_str = '</invoke>'

                            if append_str:
                                full_content += append_str
                                print(append_str, end="", flush=True)
                                on_token(append_str)
                        # --------------------------------------------------------

                    except json.JSONDecodeError:
                        # Ignore malformed JSON chunks
                        pass
```

### Why this approach is best:
1. **Saves API Cost/Time:** By keeping the `stop` strings in your API payload, OpenRouter interrupts the generation entirely on their end as soon as the sequence is detected. This saves token generation costs and execution time.
2. **Double Duty:** If the model somehow stops normally (e.g. finishes generation) but accidentally forgets to close the `<tool_call>` tag, this logic will fix the malformed output by cleanly appending the closing tag for you anyway!
3. **Graceful Handling:** Because we append directly to `full_content` and trigger `on_token`, your end-user streaming callbacks receive the appended tags smoothly just like any other chunk. Once appended, the heuristic self-corrects (the tag is now closed), preventing duplicates if any trailing metadata chunks arrive.
